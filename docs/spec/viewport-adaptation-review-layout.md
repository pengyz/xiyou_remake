## ① 布局常量 102 个普查可信度

### ①-1 "多数已有派生链"与实测相反（严重）
- **风险**：§①表称"102 个 pub const…低-中（**多数已有派生链**；252 需逐条考证）"——
  实测 layout.rs：`pub const` 总数确为 **102** ✓（含数组/颜色），但 `: i32` 的 73 个里
  **只有 3-4 个真派生**（CENTER_X=SCREEN_W/2、CENTER_Y=SCREEN_H/2、GAME_VIEW_W=SCREEN_W、
  VIEW_TOTAL_H=STATUS_BAR_H+GAME_VIEW_H），**其余 ~70 个是裸字面量**。
- **反例**（实测 census，复现：`grep -n "pub const" crates/game-core/src/layout.rs`）：
  `STATUS_GOLD_NUM_X = 237`（=240−3 内蕴屏宽）、`OVERLAY_TEXT_W = 180`、
  `HUD_SLOT_DX = 60`、`ARROW_PAIR_RIGHT_X = 160`、`ENCYC_PANEL_W = 208`、
  `SOFTKEY_ICON_LEFT_X = 2`、`HUD_FACE_AX = 40`……全无关联声明。
  **lead 问"还有多少同类非派生"——答：~70 个**，其中明显视口相关的（HUD_/STATUS_/
  SOFTKEY_/ARROW_/OVERLAY_/ENCYC_/KEY_ 族）≥30 个；GAME_VIEW_H=252 只是其中之一。
- **建议修正**：普查补"派生链实况列"（真派生 / 裸数 / 内蕴屏宽关系三分类）；"低-中"难度
  评级作废，Phase 2a 工时按 ~70 个逐条重锚重估（每个都要"改锚点 vs 保真留字面"裁定）。

## ③ 锚点布局方案：零行为差可信吗

### ③-1 "保真常量值不动只改取值来源"缺证明策略（严重）
- **风险**：零差目前只有"金样 240×320 全闸零差"一道闸——但 **45 场景金样只覆盖被驱动到的
  渲染路径**（菜单族分页/炼丹/存档位/结局/引子/图鉴等未全触达）；未触达路径的锚点重算分叉
  金样看不见。
- **反例**：`FRAME_Y` 测试注释展示的多步取整链 `box_y=(320-content_h)>>1、
  content_h=112+lh*per、lh=fontHeight+4=18 ⇒ 185`——任一步取整方向变化都可能 ±1，
  而该路径未必在 45 场景里。
- **建议修正**：零差证明 = **per-constant 等值断言**（Layout 在 240×320 求值 == 原字面值，
  覆盖全部 102+57+跨文件点）+ 金样，两者齐才称零差。

### ③-2 锚点重算的舍入/像素对齐分叉（严重）
- **风险**：现有公式的选择是**原版语义的一部分**：`>>1` 链（`string_width>>1`、
  `(320-h)>>1`、`(view_w-32)>>1`）、奇数宽向下取整、负数 `>>` 向 −∞ vs `/` 向零——
  锚点模型（LEFT/CENTER/RIGHT）若把各 site 的取整选择归一化，值就变了。
- **反例**：CENTER 于奇数宽（241）= 120 还是 121？现答案由各 site 字面公式固定；
  锚点化必须**逐 site 保留取整策略**。
- **建议修正**：Layout 契约显式建模取整（round-mode 或逐 site 公式注记）；等值断言按
  "奇/偶视口 × 各 site"双维跑（至少 240/241/320/321 四值）。

## ④ 资源缩放策略与字体度量

### ④-1 字体度量"低难度"评级与事故史实相反（严重）
- **风险**：§③称字体度量"低（度量表随缩放因子/换档）"——但 **BUG-008 刚被用户证伪为
  ①shim 根因 = 字高 10→14 错值**（cc2ab97/3423db7，教训原话"字体派生量字面量派生化"）：
  字高一路派生进框体几何，差 4px 就是整框观感事故。度量↔几何耦合是**实弹区**。
- **反例**：字高的几何消费面（普查未列）——`layout_wrapped_text_limited(…, 129,
  (line_h<<1)+12, …)`（scene.rs:1695，129=对话盒 214−85 的盒宽派生）、空图标签居中
  `32 - fontHeight >> 1`、对话盒 40=16+24、打字机行推进（typewriterPos/textLineHeight）、
  softkey 字高基准——换档/缩放时这一族全部重算，正是 3423db7 修的"字面量派生化"同型欠账。
- **建议修正**：补"字体派生量清单"（wrap 宽/盒高/居中/行距/软键基准逐项）；评级改
  **高（考证+等值密集）**；缩放换档的度量映射表带"派生量重算"检查单。

### ④-2 整数倍缩放的取整一致性未检（中）
- **风险**：视口 blit（整数倍+信箱）与 `to_screen` 反映射取整方向一致性未提——奇数窗口
  （如 721 宽 → 3x + 半像素信箱边缘）下点击热区与实际像素列错位 1px。
- **建议修正**：to_screen↔blit 取整一致性单测（奇/偶窗口 × 边缘坐标）；
  click_code 三等分热区在信箱边缘的归属钉测试。

### ④-3 资产内蕴尺寸"不参数化"结论可接受，但证据锚要留（轻）
- SEG67_PIECES/PLAYER_FRAME_W 等资产内蕴尺寸不动是对的（缩放层解决）；
  **建议**：留"资产证据锚"（ui.png/图集偏移），防未来"顺手参数化"。

## 判定

**有条件通过** ——"逻辑坐标系与视口分离 + 锚点布局 + 整数倍缩放"与保真纪律相容；但普查
**两个关键断言与实测相反**（"多数派生链"、"字体度量低风险"），**零行为差缺证明策略**。

**条件清单**（全部满足方可开工 Phase 2）：

1. **普查更正**：派生链实况列（真派生 3-4 / 裸数 ~70 / 内蕴屏宽 ≥30），难度与 Phase 2a
   工时按 ~70 逐条重锚重估；
2. **口径统一**：编辑点单位（文件级）与 const/行细目分列；测试区/期望串/金样验证面单列；
3. **零差证明策略**：per-constant 等值断言（102+57+跨文件点 × 奇/偶视口四值）+ 金样双闸；
4. **字体派生量清单**入考证面（wrap 129/209/44、盒高 40、`32-fontHeight>>1`、行距、软键基准），
   字体度量评级改高，套 3423db7"字面量派生化"教训；
5. **金样场景数钉口径**：实测 45/45（9620ed2），普查"55 场景"更正（分派普查 review-D2
   同口径病第三次出现）；
6. **to_screen↔blit 取整一致性**单测（奇/偶窗口边缘热区）。
