Android 竖屏壳当前以**虚拟摇杆**（下部方向盘 + 确定键/软键）为主操作面；画面区触屏交互（点地寻路、行点按、
标题轮播点按/滑动等）出的问题**降级不投入**，用户重新提起再做。

**为什么：** 用户 2026-10-27 明确裁定"当前我们使用虚拟摇杆操作，不用管触摸屏问题"——试玩与验收都走摇杆，
触屏专属路径的边角问题投入产出低；摇杆输入直接落键码契约（-1..-7），与原版按键语义同面，差分/夹具也覆盖这一面。
**何时使用：** 排 Android 实机问题优先级时：只在触点路径复现、摇杆路径正常的问题 → 登记即可、不修；摇杆路径也
复现 → 照常修。实机验证脚本按摇杆坐标注入（方向盘/确定键），不以触屏点按结果为验收依据。

> 【2026-10-28 补注】用户认可对抗复核建议"先修现网缺陷"（属本条"用户重新提起再做"）⇒ 触屏路径实测缺陷 BUG-038
> （点按穿透浮层）、BUG-039（点空白代按确定）、BUG-040（寻路收尾，打断键含摇杆键）已修；BUG-041（回标题声音回滚）
> 摇杆路径同样复现，按本条照常修。本条"触屏问题默认登记不修"的口径对其余触屏边角问题继续有效。
