**现象**：STAGE-B-004 收尾对照③"boot 满画布"判定只验了背景面（四角白、黑px=0），
结论 ✅ 字节级成立——但用户目测发现 modern boot 的 **logo 组/署名仍渲染在 classic
坐标**（画布 416 宽、元素心偏 −88px），适配实际未完成。背景判据对元素错位**零探测力**。

**为什么：** 画布扩展的适配有两个正交面——①背景/填充面（补满不露黑）②元素锚位面
（内容随画布重排）。像素级背景统计（黑px/四角色/带主色）只覆盖①；元素停在经典坐标
时①照样全绿。本仓适配链（SCREEN_* 常量 layout 化）修了①不自动修②（logo 时间线 ops
是另一条坐标路径）。同族教训同 004a 措辞勘误：声明面与验证面都要逐项拆解，不能以
"画面看起来对"或"背景数对"代替锚位断言。

**何时使用：** 凡"画面/布局/分辨率适配"类验证（headless 抓图对照、验收矩阵）——
判定项必须显式含**元素锚位断言**：每个可见元素组（logo/署名/图标/文字组）的
bbox 中心/边距 vs 画布锚（居中=心x=画布心±舍入、贴底/贴右缘=边距=0），加
元素间相对几何保真（间距/次序）与 classic 对照零偏离；背景满幅只是前置项之一。
量化手法：非白像素游程聚类按 y 分带 → 每带 bbox 心与画布心差。
