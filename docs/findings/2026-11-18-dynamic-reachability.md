# 动态可达性：状态 = (位置, 已触发脚本门集)

> 2026-11-18。承 `docs/findings/2026-11-18-f41-gate-reachability.md` 的更正：那一节撤回了我
> 「f41 门 25 不可达」的误判，并把原因归到「地形可走表 ≠ 能否进入该格」。本文是那次更正的**实现面**。

## 一、为什么静态图不够

静态度量把两层判定压成一层：

1. 引擎 `interact_with_cell`（`crates/game-core/src/scene.rs`）先遍历格内实体做交互；
2. **再**做地形终审，而地形终审带豁免——格内有 ty6（三昧真火）/ty7/ty8（楼梯）时跳过地形判定
   （a.java:5410/5418/5420 的 `var7++`，a.java:5470 的 `if (var6 && var7 <= 0)`）。

于是「这格能不能进」不是格子的静态属性：**门的脚本可以把 ty6 召到自己的格子上**，让墙变可进。
f41 正是这个设计（门 13 的脚本 `CES_6_10_2 CES_60_10_2`）。

## 二、模型

状态 `(x, y, fired)`：

- `fired`：本层哪些脚本门（ty83）已触发，位图（实测每层 ≤ 2 扇在墙格，位宽 62 足够；超限退回「全部已触发」近似并保留常量守卫）。
- 通行：`地形可走 || 格内静态 stair_like(6|7|8) || 已触发门的脚本在该格召出 ty6/7/8`，且不被 `blocked_doors` 封住。
- 门的触发时机覆盖两条真实路径：**走上该格**（`from_walk=true`，进入后可能再召出东西）
  与**从邻格撞**（`from_walk=false`，人不动；`case 83` 传 false，见 a.java:5463）。
- 召唤物不建模为个体：只按其对通行的影响折算（ty6/7/8 ⇒ 豁免地形），怪物按「可清除」处理。

## 三、可靠性边界（必须跟着结论一起读）

这是**乐观上界**：门控条件（`script_line_flags`、指定实体是否存在、`from_walk`、道具前置）不在模型内，
只要「触发这扇门」可能有用就允许触发。由此：

| 结论 | 在本模型下是否可靠 |
|---|---|
| 「走不到」 | **可靠**——全开、全触发都走不到，现实中更走不到 |
| 「某扇门必经」 | **可靠（保守）**——连最宽松情形都必须开，现实必然也要开 |
| 「某格可达」 | 只说明**存在一条**允许触发的路径，不代表玩家一定拿得到（可能缺前置道具/钥匙） |

不建模：战斗胜负与血量、钥匙/门的消耗（门只作为「封住/不封住」的二分）、跨层、道具前置。

## 四、实测结果（`./target/release/solver doors`）

全 55 层里「脚本门摆在静态不可走格」的只有三格，动态模型给出：

```
f41 动态探针 脚本门@(10,2) 槽13 ⇒ 可达（靠运行期召唤）
f41 动态探针 脚本门@(10,2) 槽25 ⇒ 可达（靠运行期召唤）
f48 动态探针 脚本门@(4,1) 槽38 ⇒ 可达（靠运行期召唤）
```

⇒ 三处都不是「门摆错在墙上」，而是**门自己召出 ty6 火把墙变成可进格**的自使能链。

总账不变：**门 309 扇 / 必经 32 / 同色必要 176**，判定无效层 3（f41、f48 走动态模型，f49 无出发型出口）。
这条链不在通楼梯的路径上（它通往的是下行符 22 这条资源边），所以门账不变、**变的是道具可达性**。

## 五、与求解器的关系

- `doors` / `keyflow` 现在都吃 `dynreach::fixture_scripts()`，与 `script_abs.rs` 读同一份 68 槽夹具，不另造脚本表。
- 状态仍是 `FloorStatus::DynamicGate`，含义从「静态不可靠」升级为「已按动态模型判定但结论来自乐观上界」。
- 求解器主搜索（`solve_local`）本来就靠真引擎驱动：`gate_arrive` → `try_run_scene` → `readback_script`，
  召唤物落进 `st.ents`，`stair_like(6|7|8)` 与引擎同源——所以动态性在那边是**真跑**而不是模型。
  本文这套动态搜索是给**离线分析**（不跑引擎、只读层数据）用的等价物。

## 六、缺口（下一步）

1. 门控条件仍未进模型：`flags`、实体存在性、`from_walk` 都能改判可行性；当前只在「允许触发」上取乐观。
2. 召唤物只折算通行影响，不折算「挡路的怪」——若某条链要求先清怪才能进，本模型会误判为「可达」（乐观方向的已知偏差）。
3. 尚未接入道具/钥匙预算：动态可达 ≠ 拿得起（下行符还需先拿到才用得上）。
