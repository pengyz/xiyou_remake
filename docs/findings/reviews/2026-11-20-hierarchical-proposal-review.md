## F2 商店扣费语义 —— **红**（作者自报"不闭合"是错误结论；需求 a 的商店公式无效）

逐行对账 `scene.rs:2522 apply_merchant_offer` ↔ `a.java:7307-7466`（A 级）：

1. **price=0 的真实语义是"免费"**：Rust `if good.price > 0 && !self.spend_gold(good.price)`（scene.rs:2560 附近）与 Java 完全同构——`src=1 idx=1`（id6 StatPct）走 `case 1`，**无任何 `spendGold` 调用**，购买恒成功。不是"固定金/按层/flags 门控收费"。
2. **id6 可重复购买**：flags&2=1（可重复商人）时购买后 `param^=512` 重开报价、`flags&1` 时 `pushOfferQueue(src, idx-1)` 只是把报价压入**浏览队列**（`browseOfferQueue`，a.java:7472-7500），商人实体不移除 ⇒ 同一报价可再买。⇒ atk/def 可在该商人处**无限次各 +3%**（整数逐次复利）。
3. **id12 SwapYellowKey 不是购买而是兑换**：`yellow>0 ⇒ yellow-1, gold+=100`；无黄钥则 fail_hint（a.java:7394-7404）。"gold100 从哪来"——就是效果常量，已进 `shop_goods.json` id12 evidence。
4. **全部单价已闭式落表**：`shop_goods.json` 17 行与 `a.java:7333-7455` switch 逐条一致（id7=50/id8=50/id9=1000/id10=800/id11=200/id13=1000/id14=200/id15=2000/id16=1000/id17=4000）。**不存在"价格待取证"缺口**；§8.3 / H4 / 开放问题 2 的前提（"真实扣费走 flags 分派、单价无法闭式"）是对 `price=0` 的误读，**整体作废**。

但需求 a 并非就此闭合——提案的诊断公式本身错：
- `缺口 ÷ 3% 向上取整 × 单价`：`atk += atk*3/100` 是**逐次整数复利**（每次基数变了，`floor(atk*3/100)` 非恒定 3%），目标不可达时无解而非"向上取整"。可买次数需**迭代模拟**，不是除法。
- 可买次数上限取决于**该商人格的 param>>8 flags**（逐店数据），诊断 path 必须带实体 flags；提案未把 flags 列入诊断字段。

**必须先修（红）**：删 §8.3/H4/开放问题 2 的"单价待取证"叙事，改为 A 级结论"单价全表闭合、id6 免费+可重复、id12 兑换"；重写需求 a 的商店 path 公式为"迭代模拟买次 + 逐店 flags 字段"，并说明 id6 免费可重复对优化器的影响（属性可无界增长，需支配/上界论证接 §3.2——现文完全未讨论免费无限 StatPct 对状态空间与最优性的冲击）。
