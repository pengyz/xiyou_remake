## F1 红：DP 终态序「hp 优先」无判据守

**实现本身是对的**：`crates/game-solver/src/exact_pickup.rs:341-343` 是 `hn.cmp(&hb).then(nm.cmp(&bm)).then(sb.cmp(&n.steps))`，hp 在 floor 之前；`crates/game-solver/src/objective.rs:91-94` 的 `cmp_exit_floor` 也是 `hp → gold → 满足 floor → steps`。

**但没有判据能打红「floor 插到 hp 之前」**。在 `/tmp/s6amut` 把 `exact_pickup.rs:341-343` 改成：

```rust
nm.cmp(&bm)
    .then(hn.cmp(&hb))
    .then(sb.cmp(&n.steps))
```

然后跑 `cargo test -p game-solver --release --test exact_pickup -- --nocapture`：

```
[S6a] f3 floor=Some([2,0,0]) ... hp=4027 gold=1256 keys=(2,1,0) steps=83 ... adopted
test result: ok. 13 passed; 0 failed; 0 ignored
```

13 条全绿，包括本该守这条契约的 `s6a_exact_dp_key_floor_f3`（`crates/game-solver/tests/exact_pickup.rs:618` 的 `out_hp == 4027`）。由于 DP 的 `key_floor=Some` 调用点只有这两条 S6a 测试（见 F5），其他测试 target 也不会补抓这个变异。原因很具体：f3 夹具里**满足 floor 的终态恰好也带最大 hp**，所以「floor 先于 hp」和「hp 先于 floor」在这个夹具上选到同一个 hp；该夹具根本没有 hp/floor 权衡。

另一个结构性原因：DP 明确不走 `cmp_exit_floor`（`crates/game-solver/src/exact_pickup.rs:313-314` 注释：「这里不调 `objective::cmp_exit_floor`（它含 gold），只共用 floor 判定」）。唯一真正断言「hp/gold 压过 key_floor」的测试是 `crates/game-solver/tests/objective.rs:509-532` 的 `s6a_keys_never_outrank_hp_or_gold_with_floor`，它只测 `cmp_exit_floor`，**不覆盖 DP 比较器**；所以 M2 绕过它。

**最小修法（合入门槛）**：加一条 DP 级合成夹具——同一层里「保留黄钥」与「花掉黄钥开门拿 +hp」互斥（用现有门/拾取物构造），`key_floor=Some([1,0,0])`，断言选中的是 **hp 更高的那条（即使 keys 不满足 floor）**，反向再断一次；或直接对 `exact_pickup` 的终态挑选做变异可测的判据。只加 `cmp_exit_floor` 单测解决不了 F1。

## F3 黄：逐色 ≥ 语义正确；floor 不可达时无具名标记

- 语义是**逐色 ≥**：`crates/game-solver/src/objective.rs:76-77` 为 `keys[0]>=floor[0] && keys[1]>=floor[1] && keys[2]>=floor[2]`。独立边界：`floor=[2,0,0]` 时 `(2,0,0)` 胜 `(0,1,0)`、`(0,1,0)` 判定不满足；`meets_key_floor([1,9,9],[2,0,0])==false`（不会因为蓝/红多就补黄）。
- 语义有判据：把 `&&` 改成 `||`（M3）后，`s6a_keys_never_outrank_hp_or_gold_with_floor`（`tests/objective.rs:524`）与两条 exact 测试（`tests/exact_pickup.rs:619`、memo 测试）**3 条红**，说明「任一色」的实现会被抓。
- **缺具名不可达标记**：f3 用 `key_floor=Some([9,0,0])`（远超本层可见黄钥量，实测出层 y=0）实跑：

```
[S6a-unreachable] hit=true ok=true trunc=false hp=4027 y=0 gold=1256 steps=81
exit=Some((11, 11)) stat=ExactStat { adopted: true, reason: "adopted", ... }
```

即**静默返回「hp 最大、钥匙不够」的解**，`ok=true`、`reason="adopted"`，没有 `key_floor_unreachable_in_layer`（全仓 grep 0 命中），单层 `ExitSolve` 也没有短缺口字段；`key_shortfall` 只存在于 witness（`crates/game-solver/src/witness.rs:224,407`），且被 `tests/objective.rs:277` 的 `key_shortfall_reported_not_blocking` 钉成**不阻断**。方案 §3/§4.2 要求 exact_pickup 在 `need[c]>0` 但本层无该色拾取物时给 `key_floor_unreachable_in_layer`。

**最小修法**：在 `ExactStat.reason` 或 `ExitSolve` 增加具名 `key_floor_unreachable_in_layer`（区分「本层拾取物总量不足」与「本路线没走到」），并加 floor=[9,0,0] 的断言；若判定属于 S6b，请在 S6a 报告/注释里显式写「未实现、不得据此声称 floor 会被报告」。
