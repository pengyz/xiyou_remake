## 0. 基础面核（layout.rs 现状对方案的约束）

layout.rs 已为扩视口预留推导分层（:12-32"未来可变"、CENTER_*/hud_base_y() 派生类）
✓ 方案有好基础；但 :312-331 **设计常量段**明文"与 SCREEN_* 无维度推导关系，扩视口须
逐条重新考证，**不可**机械缩放"（OVERLAY_TEXT_W=180 / SLOT_LIST_MAX_H=208 /
ENCYC_PANEL_W=208 / ARROW_PAIR_* 等）——R3"UI 全公式锚"必须**逐条**处理这一段：
公式化或显式保留字面量并给新布局下的合理性论证。此段是方案最容易被"机械缩放"击穿的面。

## 1. ① 公式边界【硬要求 1：定死 + 矛盾消解】

- **内部矛盾**：`max(map_*,26)×16+UI 带` 与 "窄图屏宽随地图无黑边" 不能同真——
  24 宽变体按 max = 26 格屏宽 ⇒ 2 格黑边，正违"无黑边"。须定死：宽随图（map_w×16）
  还是带 26 下限？下限作用于宽/高哪维？"变体 24×26 自适配"的逐值表（SCREEN_W/H
  两变体具体数值 + UI 带高度构成）。
- **动态画布爆炸半径清单**（方案缺）：SoftGraphics 画布分配、shell `CANVAS_W/H`
  常量（shell/win/src/main.rs:46-47）、view.rs Viewport/鼠标逆映射、oracle 状态转储/
  帧 PNG 尺寸、全库坐标断言——清单+逐面处置（legacy/公式/豁免）入登记册。

## 2. ③ 相机公式化保真【硬要求 2：Legacy 等价判据——本方案命门】

相机"跟随行为零改动"的机器判据必须是**重构等价**而非"看着对"：

1. **`Layout::legacy()` = 现行常量**（240×320 + GAME_VIEW_H=252 + 现值全套）——
   公式化后的相机/边界派生在 legacy 参数下**逐值/逐拍等价**：walk_camera_golden 4 测、
   game_view 相机钳制测（game_view.rs:257 居中钳制 (8,-210) 等）、ease 相机序列
   **断言一字不改仍绿** = "公式化本身零语义变化"的证明面；
2. 魔法数（scene.rs:4502-4568 的 106/16/32、MAP_VIEW_CY29 系）公式化后在 legacy 下
   **必须化回原值**（代入验证断言）；
3. 现行测试面默认走 legacy（保稳定、限 churn），动态变体另测——金样期望的任何改动
   按 001 R2 机制枚举+偏离 ID 注释（禁静默）。
4. **trace 字段分层**（方案缺）：视口变了，相机类字段（cam_x/y、ease_*）在新参数下
   必然变——须列出 trace 字段的"语义字段（必须逐 tick 不变）/ 渲染派生字段（豁免）"
   分类表，否则"语义/玩法零改动"无判据。
