# S6b：key_floor 接进外层链（真链首验：f4 打通、断在 f5）

> 2026-11-23。方案依据 `docs/superpowers/proposals/2026-11-23-s6-pickup-alignment-plan.md`（选型 C=A′+B′）。
> 产物 JSON：`docs/findings/outer-chain-s6b.json`（`run` 全题语义，非 `--outer-seg`）。

## 1. 接了什么

单一口径函数 `crates/game-solver/src/objective.rs::key_floor_for_up_edge(levels, floor, toward)`：

- `toward != Some(floor + 1)` ⇒ `None`（回拾/下行**不强加**需求 —— 用户裁定 m04638：钥匙是跨层动态资源，
  单层硬门槛会制造假不可行）；
- `next_demand(floor)` 为 `Known` 且逐色非全零 ⇒ `Some([黄,蓝,红])`；
- `Known` 全零 / `Undefined(_)` ⇒ `None`（全零不造需求；未定义原因由 `demand_undefined` 具名落盘）。

调用面三处全部走这一个函数：`witness.rs`（单链驱动 `run_witness*`）、`outer_witness.rs`（块搜索驱动）
两处的驱动循环各自算一次并**同时**传给 `layer(...)` 与 `record_floor(...)`；`outer_chain.rs` 的
boss 锚任务改调 `solve_local_boss_toward_shops_floor`（该路径**不消费** floor，只如实打
`key_floor_not_consulted="boss"`）。

层解器类型 `LayerSolver` / `OuterLayerSolver` 末参追加 `Option<[i32;3]>`，生产闭包改调
`solve_local_exit_toward_shops_floor`。witness 落盘字段（v4）现在能看到三点区分：

| `key_floor` | `key_floor_not_consulted` | 含义 |
|---|---|---|
| `null` | `null` | 没请求（回拾/无上行边） |
| `[2,0,0]` | `null` | 请求了且**真消费**了 |
| `[2,0,0]` | `"pure_pickup"`/`"boss"` | 请求了但**没看**（这两条快路径不读 floor） |

## 3. 结论（只写测到的）

1. **f4 打通了**。S5 期间的断点是 `blocked=floor 4 reason=no_exit_toward`（内层 0 黄钥匙进不了 f4 的门）；
   现在 f4 有了 83 步出层解。这是 S6 的目标达成面。
2. **f3 的交付值与方案预测一致**：预测「多带 2 把黄钥 ≈ +2 步、0 hp、0 gold」；实测
   `keys_out=[2,1,0]`、`steps=83`（与改造前 83 同）、`hp=4027`（同）、`gold=1256`（同）。
   即：**钥匙只吃步数维，不吃血量与金币**。
3. **f3 是唯一非空 `key_floor`**：`[2,0,0]` 与 `keydemand` 对 f4 的独立分析（2 黄）逐值一致，
   且 `key_floor_not_consulted=null` ⇒ 精确 DP **真消费**了它（不是打了个标记混过去）。
   其余层 `key_floor=null`：f51..f54/f1/f2 走向上的目标层不需要带钥匙，f4 的 `demand=[0,0,0]`。
4. **链现在断在 f5，且断法不同**：`blocked=floor 5 reason=truncated`（层 5 搜索撞层界），
   不是原来的 `no_exit_toward`。`truncated` 是「搜索没跑完」而非「穷尽无解」，所以
   **不能**把它当 f5 不可解的证据（S3 结论语义二维化就是为这种情形立的）。

## 4. 遗留（下一片）

- **f5 为什么撞层界**：可能是 (a) f5 本身搜索空间大；(b) f5 的 `key_floor`（= f6 入场需求）
  把状态空间撑大。必须分别测「带 floor / 不带 floor」的 f5 单层读数（`pops`、`states`、
  `hit_layer_cap`）才能归因——**不许**先抬 layer 上限再解释。
- 本链 `prefix_replay=null`、`replay=null`：因为 `status=capped`（不是 witness），
  回放只在有完整 witness 或 blocked 前缀时产出。f5 解决后才能验「全程回放绿」。
- `--outer-seg` 段链这次没跑（`run` 全题语义先验单链一致性）；段链的 `key_floor` 只影响
  `Some(f)` 分支，boss 分支如实打 marker。
