> 方法：oracle 输入脚本 + 状态向量 trace（`FLD NNN` 字段声明序索引，语义化阅读见

## 1. 输入模型（A 级，keyPressed + run 主循环）

- `f_int_05`（N-0104 keyValue）：**本 tick 按键电平**。keyPressed 写入
  （a.java:4639 `f_int_05 = f_int_06 = code`），run 主循环每 tick 末清零（a.java:4251）。
  各子状态机的"当前键"switch 全部读它。
- `f_int_06`（N-0105 keyHeldCode）：**粘滞键**。keyPressed 写入、特定消费点清零
  （a.java:3326 双清、case 49/55 各自清）。菜单列表用它做连续滚动。
- 事件投递时点：oracle 在 tick 边界（serviceRepaints）回调 keyPressed/keyReleased
  （shim Canvas.java:84-90），与原版主循环 repaint/serviceRepaints（a.java:2421-2422）对齐。
- 按键→行为不是直接映射：**每个 gameMode/子状态有自己的消费 switch**。同一键在不同
  状态下语义不同（-5 在菜单=确认、在对话=翻页、在镜头态被相机处理器吃掉）。

## 3. 存档系统三链（A 级，m_110/m_111/m_114/m_115 读写序逐字段对齐）

| 存储 | 写 | 读 | 内容 |

| `MOT_IF` | m_111 之后的写路径 | **m_111（启动）** | 6 槽位表：每槽 1B 有效位 + 有效槽 1B 层号 + 2B 装备 + 7×int 数值快照 |
| `MOT_L{n}` | **m_114（mode7 保存确认）** | **m_115（载入）** | 278B 完整状态：难度/层/位置/朝向/装备/HP/ATK/DEF/三钥匙/金/炼丹/背包(f_int_89 对)/128B 脚本标记/物品栈/56 层脚本缓存 |
| `SKY_WAR` | **m_110** | run case21 | 4×boolean + byte N + N×int（难度表）+ 3×int（层里程碑） |

**载入有效链**（缺一不可，2026-10-10 实测）：

```
MOT_IF 槽位有效位（f_bool_arr_07 的唯一来源，m_111）
  → 菜单「继续游戏」→ mode 8 存档槽列表（f_int_134 选槽，默认 0）
  → 确认 → m_115 读 "MOT_L" + f_int_134（默认槽 0 ⇒ MOT_L0）
  → scaleEnemyStats(difficultyMultipliers[f_byte_26]) → mode 3
```

- 槽位默认 `f_int_134 = 0` ⇒ 预置必须写 **MOT_L0**（实测 MOT_L1 无效）。
- `f_bool_arr_07` 无 MOT_IF 支撑时槽位显示 "---" 且确认无效（a.java:3821 门）。
- 生成器：[`reference/oracle/preset_rms.py`](../../reference/oracle/preset_rms.py)
  （确定性，逐字段对照 m_114/m_110 写序）。

## 5. 对话/行走/相机三层状态机（A 级 trace + 代码双重验证）

**对话覆盖层** `f_byte_16`（N-0104 dialogPhase，mode 3 叠加或 mode 11）：

| 值 | 含义 | 出口 |
|---|---|---|
| 0 | 脚本步进（executeScriptInstruction） | 依指令切相 |
| 1/6 | 打字机（f_int_33 推进；任意键快进 f_int_05!=0） | 文本完→键翻页 m_096(page+1) |
| 2 | 选项/分支（m_106） | 键选择 |

| 5 | 战斗/动画等待 | f_bool_16/17 |

**行走子状态机** `f_byte_11`（N-0105 walkPhase，mode 3）：
0=待机/探索（-5 触发 m_027 手动输入处理或 m_032），1=步进动画（每 tick ±8px，
f_int_43 累计 32px=一格→applyStepCellEffects），2=探索确认弹窗（f_bool_06），
3=脚本寻路行走（消费 f_byte_arr_42/f_int_148），5=战斗（tickBattle）。

**相机对**：`f_int_123/124` = 当前相机（每 tick 向目标趋近 (Δ>>2)+2，m_105），
`f_int_125/126` = 目标（=玩家像素坐标，m_100 系写入）。**实测相机 10 tick 即可走完**
——序章"慢镜头"假象实为对白页逐步推进（每步一键）。

## 6. mode 16 空队列死路（BUG-006 关联发现，A 级实测）

菜单「载入进度」→ mode 16 后：进度 `f_int_143` 恒 0、队列 `f_int_144/145` 恒 0/0
——**该路径入队逻辑从未被触发**（mode16 的唯一推进是队列消费，而只有 mode8 的
有效槽确认 [a.java:3821] 和 m_067 会排队列）。-7 弹回菜单（f_byte_01=1）。
结论：「载入进度」文字项与可用载入路径（mode 8）错位——与 BUG-006 一并构成
"进度不可达"家族；且 mode 16 实为设置列表（BUG-007 错位家族）。
Stage A 保真，载入走 mode 8 路线（已验证可达）。
