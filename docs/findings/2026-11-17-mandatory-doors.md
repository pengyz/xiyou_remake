# 必经门清单（54 层）——哪些门非开不可

> 目的：把「钥匙够用即可」从口号变成可核对的清单。判定口径沿用 C4-a 对怪格的
> 「充分 + 必要」判据，只是把对象从「挡路的怪」换成「挡路的门」。

## 1. 判定口径

- **必经**：单独封住这扇门 ⇒ 从本层到场梯走不到本层出发梯。非开不可。
- **同色必要**：封住该色全部门 ⇒ 走不到出发梯。该色钥匙至少要有一把。
- 起点/终点取自实体：`STAIR_DOWN`(ty=8) = **到场格**，`STAIR_UP`(ty=7) = **出发格**
  （`crates/game-core/src/enums.rs:166-168`）。不用 `LevelSpec::start`——那是全局入口
  (1,11)（来自 51 层状态），逐层分析会在「到场梯不在 (1,11)」的层上判错（f16 就是这样暴露的）。
- BFS 只把**地形 + 门**当约束：怪不是固定墙（怪是击杀决策），拾取/商店格可穿。
- 楼梯格豁免地形（`solve_local.rs:1183`：地形终审 = 楼梯豁免 `stair_count>0`）。

命令行：`cargo run --release -p game-solver -- doors [--out PATH]`，
产物 `docs/findings/mandatory-doors.json`（逐门 ty/color/x/y/necessary/color_needed）。

## 3. 三条结论

1. **蓝钥匙需求 = 0。** 45 扇蓝门没有一扇必经——全部是可绕过的支线。买蓝钥匙
   （f6 ¤50 / f15 ¤200 / f31 黄+蓝 ¤1000 / f39 蓝×3 ¤2000）在「能不能通关」这件事上收益为零，
   只对「支线拿道具/降损失」有价值。这与用户定的「钥匙够用即可」直接对上。
2. **红钥匙需求 = 4 把，供给 = 6 把**（f8/f14/f34/f37/f42/f51 免费拾取）。
   f10 红门（第 1 把，f8 就够）、f20（第 2 把，f14 正好在前面）、f40（第 3 把，f34/f37）、
   f51（第 4 把，f42）。**f12 商店那 800 金买红钥匙是纯冗余**——这条路已被
   `5dee77c` 的自我更正确认，此处从门的拓扑面再次独立证实。
3. **黄钥匙需求 29 把，供给 176 把**（ty=26 拾取数）。黄门是必经门的主力，但黄钥匙严重过剩；
   f7 商店「黄×5 ¤50」在任何经济下都是便宜的补充手段。

## 4. 保留项（未证伪，但当前未覆盖）

- **f49 / f50 没有 STAIR_UP**：换层只能走脚本/特殊事件。
  【2026-11-17 改判】f49 现报 `FloorStatus::NoExit`（「无出发型出口」），**不再**报
  `baseline_unreachable`——前者是「本层给不出门判定」，后者是「门全开也走不到」，
  两者混同会把「未建模的换层方式」误读成「地图封死」。
  CLI 输出与 JSON（`status` 字段）已区分 `ok` / `no_exit` / `baseline_unreachable`。
- 本判定只看**拓扑必经性**，不看「钥匙够不够到达那一刻」。例如「f20 需要第 2 把红钥匙」
  只说明拓扑上要开，不说明你手里有没有——那要另做「按层累计供给/需求」的对账（下一步）。
- 怪被当成可穿：一只打不过又挡住唯一通路的怪，会让「必经门」判定偏乐观。真正的
  不可通过性属 C4-a 的 `blocking_kill_slots` 范畴，两份清单需交叉核对。
