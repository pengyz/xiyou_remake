# 块合并与接口导出表（S1 片）

> 隶属《分层收缩搜索》提案 §7 S1（docs/superpowers/proposals/2026-11-20-hierarchical-solver-proposal.md）。
> 机器可读数据：[block-interfaces.json](block-interfaces.json)（schema `xiyou/block-interfaces/v2`）。
> 本版为 **2026-11-20 修复版**：修正 maplv 网格坐标系（R1）、补录非可走地形脚本门（R3）、全部统计由脚本直出（R2）。

## 1. 方法与口径（全部复用引擎实现，未自造）

- **网格**：`assets/raw/maplv{n}` 头部 u16×2 为 tile 尺寸（raw），cell 尺寸 = `raw>>1`；
  真实网格 13×13 cell（f51 为 12×13）。地形字节 `grid[y*width*4 + x*2]`，
  可走 = `tile_walkability[tile]==1`。证据：`crates/game-core/src/scene_persist.rs:291-301`、
  参考 `a.java:6973-6990`（rebuildWalkability）。**维度守卫**：解析时断言
  `(w,h) ∈ {(13,13),(12,13)}`，越界即失败（JSON 每层带 `width/height`）。
- **实体**：`assets/raw/sprite{n}`（u32 count + 记录流）；param 语义复用
  `crates/game-core/src/sprite_spawn.rs:23`（ty7/8 目标层=extra 低位；ty83=script slot）。
  分类复用 `data/tables/sprite_defs.json` 的 `render_category` +
  `floor_category_override`（仅 ty72@f50→cat8），锚点 `crates/game-core/src/entity.rs:245`、
  `resource_cfg.rs:314-322`、`script_host.rs:138`。
- **连通块**：对「可走且非阻断」格做 4 邻接 floodfill。阻断格 = 门 ty1/2/3、
  封印门 ty4/81、脚本门 ty83、商店 ty77/78、硬阻挡 ty9-12 与 cat32（ty72 仅 f50 豁免为怪）。
  怪（cat8 = ty41..75）**可走**，不切块。
- **割点**：阻断格按 4 邻接聚簇；簇的邻接分量 ≥2 时，簇内每扇门/封印门/脚本门
  对所有「非归属侧」邻接分量记 `cut_doors`（归属侧 = 入口侧分量优先，否则最小 id）。
  **必杀怪（删怪判据）**：仅对非阻断格判「删除该怪后其邻格跨 ≥2 分量」。
  **结果：全塔 0 个**（v1 曾标 f51(7,10)/f52(11,7)，实为同格 ty83 脚本门造成的块分裂，
  已如实改记为脚本门割点——见 §4）。战斗代价下界不在本表展开，留给 S2。
- **导出面三分类**（用户裁定）：常数类（29-32 丹 = 拾取即生效 + 所在层 tier；
  装备 33-40/79-80 tier 固定）；时点类（商店 77/78 全部商品按 `shop_goods.json` +
  `apply_merchant_offer`（scene.rs:2522，StatPct `atk+=atk*pct/100` :2568）记录；
  item19 千年月桂露、item25 幸运币）；拓扑类（16/17/18/20/21/22/85/86，
  effect key 来自 `data/tables/items.json`，规则层 `effect_registry.rs`）。
- **出口**：ty7/ty8 楼梯（`param&0xff` 目标层，floorgraph 同口径）、ty83 带 LAY 的脚本边、
  boss 击杀触发（`crates/game-core/src/rules/boss.rs` event_of + EVENT_SPAWNS）。
- **钥匙**：ty1/2/3 → 消耗 26/27/28（`enums.rs:185-191` DOOR_YELLOW/RED/BLUE）。
- **零钥匙可达**： dynreach 乐观口径（怪视为可清、道具视为已有、f41/f48 的
  召火自使能门按动态可达处理）——本表块合并只用静态地形+阻断格，动态豁免
  （ty6/7/8 spawn 格）已在可走集合内计入（楼梯/火格豁免）。

## 2. 一致性判据（逐条自验结果）

1. **cells_sum**：54 层（f0 另计）每层 `Σblocks.cells == walkable`，PASS（违例=无）。
2. **entity_membership**：每个拾取/商店/门实体恰好归属一个块（按格去重），PASS。
3. **cut_ge_keydemand**：49 个可比层（keydemand ok 层）逐层核对
   `cut_doors(d1,d2,d3) ≥ (min_needed_y,b,r)`，PASS（违例=无）；
   交叉点 f4 需黄1（cut d1:7 ✓）、f46 需黄1+蓝2（cut d1:8 d3:2 ✓）。
   > 【2026-11-20 更正】上行为笔误：keydemand 实测 f4 needed=(y=2,b=0,r=0)、f46 needed=(y=3,b=0,r=0)（cargo run -p game-solver -- keydemand 复核；复核报告 2026-11-20-block-interfaces-review.md 黄1）。PASS 判定不受影响（cut d1:7≥2、d1:8≥3 仍成立），正确交叉点为：f4 需黄2（cut d1:7 ✓）、f46 需黄3（cut d1:8 ✓）。
4. **54 层全跑完**：f0 = 隐藏/调试层（solver 不建图，floors 1..=54；含 StairUp(1,1)→f1，
   不入 floorgraph 105 条对账）；f44 有上下行楼梯但 b1 孤立 5 格小袋（无出口）；
   f49 无上行楼梯（顶=击杀触发/脚本）；f50 终局单块 9 格，无入口无上行
   （入口为 f49 剧情传送，keydemand 同判 no_entry）。
5. **floorgraph 对账**：对账对象 = `cargo run --release -p game-solver -- floors` 的
   105 条楼梯/脚本边。本表重放 stair=104 + script(LAY)=1 = 105，逐条格坐标
   写入 JSON `edge_reconcile[]`，PASS。f0 的 1 条边另计不入账。
