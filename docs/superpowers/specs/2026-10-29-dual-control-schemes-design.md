## 3. 功能查询

### 3.1 判定口径

情境由 core 状态派生，不由图标派生：
- 地图类：`game_mode`（Map / Dialog）× `walkto_owns_dp3`（点地寻路占用 dp3）× walk_phase（含 2 观察、5 战斗）× 怪物选中 × 排队动作。
  点地撞击一律在 Map wp0 执行（§5.2），所以点地开出的战斗与手动战斗同为 Map wp5，不再按来源区分。
- 浮层类：`overlay_kind` × kind 4 的 (src, flags) × kind 3 的道具类别 × kind 1 的图标子类 × 分页状态。
- 页面类：各 game_mode；BootMachine 侧各 mode。

查询结果的每个键位给出 `Action`：`Key(code)`（发原版键码）或无键码动作 `Stop` / `Cancel` / `Fight` / `StopThen(code)` / `Undo`。

## 4. 布局与工具栏

### 4.1 触屏档布局

- 工具栏：贴底，位于手势区之上，高 64dp。视口 = 内容区顶至工具栏顶，高 V_t = 内容区高 − 64dp − G（G = max(inset_bottom, 32dp)）。
- scene 档倍率 s_t：在 [s_read, min(4, s_boot)] 中取**最大**的 s，使 ⌊W / (32·s)⌋ ≥ C_min 且 ⌊V_t / (32·s)⌋ ≥ 10（原版 320 高 = 10 行；
  不要求整层高度可见，竖向由相机跟随）。无满足者 ⇒ s_t = 现公式的 s。
  格阵 = (min(⌊W/(32·s_t)⌋, cols_max), min(⌊V_t/(32·s_t)⌋, rows_max))。C_min 待用户裁定（§12）。
- boot 档不变（现公式，于视口内居中）。摇杆档布局不变。
- 三档窗口估算（inset 取典型值；plan 中按公式钉测试）：

| 窗口 | V_t（约） | C_min = 8 | C_min = 9 |
|---|---|---|---|
| 1200×2536@480（Xiaomi 14） | 2248 | 4 倍，9×16 | 4 倍，9×16 |
| 1080×2400@420 | ≈ 2060 | 4 倍，8×16 | 3 倍，11×16 |
| 720×1600@320 | ≈ 1400 | 3 倍，7×14 | 3 倍，7×14 |

- HUD 在最窄格阵宽度（8 列 = 256 / 9 列 = 288 逻辑 px）下出截图验证左右块无重叠；重叠则该宽度不可用（C_min 上调）。

### 4.2 工具栏

┌───────────┬────────────────────────┬───────────┐
│  左大键    │  中间：0–4 个小按钮     │  右大键    │
└───────────┴────────────────────────┴───────────┘

## 5. 地图点按规则

### 5.1 安全通行与寻路

- **"存在且可见"** = `visible ∧ state ≠ 1 ∧ ¬removed`。类目取 `GameScene::entity_category`（含层覆写）。
- 专用通行函数 `tap_passable(x, y)`：

| 格 | 途中可否经过 |
|---|---|
| 无"存在且可见"实体 | 只看地形（不可见实体对寻路不存在：隐形路径 = 墙，隐形墙 / 剧情点 / 踏板 = 地面；碰上后效果与手动走一致，由 P3 保证不穿格） |
| "存在且可见"实体全为类目 2 / 4（道具 / 装备）或已显形型 6 | 可经过；沿途拾取是预期行为 |
| 有其他"存在且可见"实体（门、封印、怪物、商人、告示、炼丹炉、楼梯、火、可挖墙、类目 32） | 不可经过，只能作目标 |
| 陷阱伤害格（陷阱纯谓词，按当前装备） | 不可经过；目标格本身除外 |

- 寻路 = 以 `tap_passable` 为通行的 BFS 最短路（无扩展上限；同长路径按固定方向序取，保证确定性）。不再用 `find_path` / `plan_route`。
- 沿途拾取装备 40 会改变后续陷阱判定：路线在规划时按当时装备算，途中不重算（保守，可能多绕路，不会多受伤）。
- 原则：看不见的东西寻路不知道，看得见的危险寻路避开。

### 5.2 点中目标的行为

| 点中 | 行为 |
|---|---|
| 可达空地 | 走过去 |
| 不可达空地 | 走到可达格中离目标曼哈顿距离最小者（平局取路径最短，再平局行主序）停下，目标标记闪红 |
| 墙（远近同） | 走到墙边可达邻格，再撞一步；无可达邻格 ⇒ 按不可达 |
| 门、商人、告示、楼梯、火、封印门、类目 32 | 走到邻格，再撞一步触发交互 |
| 炼丹炉（宽 3 格） | 停靠格优先取三格任一的正下方（按上行排序取最近），朝上撞；三格下方都不可达 ⇒ 停在最近可达格并闪红 |
| 怪物（含多格怪的任一格、陷阱怪） | 首点 = 选中；再点同一只或按「开战」= 走到邻格撞上。自动战斗开 ⇒ 一点即战。打不过：撞上后由原版提示框"你无法战胜它"告知（P1），不另加闪红 |
| 道具格 | 走过去（拾取） |
| 自己 | 点地寻路中 = 停下；空闲 = 无动作 |
| 点地寻路中点别处 / 滑动 / 按「背包」「菜单」 | **排队**（见下） |
| 战斗中（Map wp5）点画面 | 无动作（`blank_tap_key` 本就为 None），闪红叉 |
| 换层遮幅 | 无动作 |

- **撞击语义**（依赖 P0 / P3）：撞击**一律在 Map wp0 执行**，不作为路线末步。路线只走到停靠格，由 `finish_walkto` 回 Map wp0；随后
  （同拍或下一拍，plan 中定）执行撞击：置 `facing = 撞击方向` → 开 route 段 → `try_step`。效果与按方向键撞同一格一致；炼丹炉不经
  Dialog → Alchemy（无须给经典边表加边）。撞后未开战 ⇒ 立即收段；**零长位移笔不入撤销栈**（`route_event_suspend` / close 判 from == to）。
- **排队**（排队改道、停下后打开、路线中滑动共用）：输入到达时立即 `interrupt_route`（BUG-040 排空：走完当前步后 `finish_walkto` 回 Map wp0），
  core 记下待执行动作（新目标 / −6 / −7 / 滑动方向），只保留最后一次；在 `field_tap_allowed` 首次为真的那一拍执行。
  失效即丢弃：排空没有在当前步结束时落到 Map wp0（开战、剧情接管、换层、浮层），或排空期间有方向键 / 其他按键输入。
- **赠予 / 报价（kind 4，src 0，flags&2）点空白不代按**：按 BUG-039"要做决定的框点空白不代按"原则，`blank_tap_key` 对该子类返回 None
  （现按图标判，会代按 −5 = 接受）。Stage B 偏离，记入 STAGE-B-008。
- 选中怪物的有效性**每拍校验**（楼层号、实体类型、所在格、state ≠ 1、Map wp0、无浮层、操控模式未变）；任一失效即清。点别处 / 滑动 /
  任何方向键 / 打开菜单或背包 / 撤销 ⇒ 清选中并执行该输入。

### 5.3 手势

- Android 视口接 Move 事件（现只在 Up 记点按，`native.rs:595-606`）。分类：位移 < 阈值 = 点按；≥ 阈值 = 滑动（地图）或拖动（观察模式）。
  滑动 / 拖动不再产生 Up 点按。阈值以 dp 计，plan 中定值并测试。
- **滑动**（地图空闲）：朝主方向 `probe_step` 一格（P0 修复后先置 facing）。点地寻路中滑动走 §5.2 排队。
- **拖动**（观察模式）：直写相机偏移（modern 专用入口），钳位与原版 wp2 平移相同；按拖动主方向同式改 `facing`（与 wp2 平移臂一致，
  `scene.rs:4927-4963`）；点按无效。
- **摇杆模式**：同一套点按 / 滑动 / 拖动规则；不显示自动战斗，点怪恒需确认。

### 5.4 与既有机制的交互

- BUG-043：点地寻路期间教程箭头规则不变（逐格按步向消费）。BFS 替换 find_path 后，BUG-043 宿主测试中依赖 find_path 步序的期望须按新路线

## 6. 反馈

- **目标标记**：被点格画框，到达 / 打断 / 撤销 / 改道后消失；层级 = 实体层之上、HUD 与浮层之下。
- **闪红**：同框红色，约 0.5 s，按游戏帧计数（确定可复现）。
- **选中怪物**：框闪烁；持火眼金睛时旁标预计掉血（`predict_hp_loss`，与观察模式同源）。
- **震动 / 按键音**：点按被接受时一次（沿用两开关）；被拒绝只有视觉。
- 状态在 core、由 core 绘制，只在 modern 布局出现；classic 零绘制 op。

## 7. 撤销

- 依赖 P4 BUG-045 修复（战斗逆放 + 换层 / 读档 / 存档 / 剧情清栈）。
